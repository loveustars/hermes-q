## 为什么留着

这是"修复前"的原始产物。**修完 bug 后旧数字通常再也拿不到**，
留着它才能回答"当时到底错成什么样"。修复后的对照结果在同级的
`runs/d_param_search/`（重跑产物）。

## 这批数字错得有多离谱

| 现象 | 数值 | 说明 |
|---|---|---|
| `total_return` 最高 | **55,446 倍** | 本金 10,000 → 终值 5.54 亿（`η=0.05, band=0.03`） |
| `max_dd` 最低 | **−9.59e198** | 这个量级的回撤不可能是经济现实 |
| 两组 `total_return` | **NaN** | 终值溢出，`best_by_sharpe` 因此为 `null` |
| `mean_total`（funding 对比） | **NaN** | 均值被污染 |

把这些当成"策略表现"是**方向性错误**：它们实际度量的是
`MarginBook` 每强平一次凭空产生的钱。

## 关键：**1x 也中招，不只是 3x**

这批跑的是 `LEVERAGE = 1.0`（D2 阶段）。曾经以为"低杠杆受影响较小"是**错的**：
缺陷 2 让空头一开仓就被强平、缺陷 1 让每次强平都造钱，
两者相乘**与杠杆倍数无关**。所以这一整批 1x 结果同样不可用。

## 复现"修复前"的方法

`scripts/fix_margin_verify.py` 内联保存了初版的 `LegacyMarginBook`，
随时可以重跑出对照，不必依赖本目录：

```bash
python3 scripts/fix_margin_verify.py --bars 25000
```
